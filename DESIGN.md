# Peerboop P2P

## Product surface

Mode: Read for the repository; Operate for native Grok chat. The product is one Markdown skill. Grok owns its layout, fonts, theme and native choice cards. There is no custom website or renderer.

The character and brand is **Peerboop**. Use **Peerboop P2P** in the public listing, and **Your USDC P2P desk, inside Grok.** as its descriptor. Galleon Labs and Andrew Wilkinson belong in creator credits, never appended to the bot name.

## Native conversation

Lead with the requested amount or verified state, followed by the detail that changes the decision, then one useful action. Separate these with blank lines. Most replies are 20–40 words; up to 60 when a real explanation needs it. A currency flag or one helpful emoji is welcome. No wide tables, progress narration, generic caveats or repeated slogans.

A blank welcome shows **Hey, I’m Peerboop 👋 Live USDC prices, fees and payment apps, right here.** and one native card, **What can I get you?**, with **Buy USDC**, **Sell USDC**, **Cheapest route today** and **Track a deposit**. Clear requests skip the welcome. Each turn is one finished message: no holding messages while a lookup runs. Watches are available on request but are not advertised in the welcome because native delivery is not yet verified. Verified snapshots use no Estimated or Indicative label. Keep requested pay/receive amounts on separate rows; fee amount and percentage get one short included-fee line. Market reference values must be called market value rather than a bank payout. Sell replies show market value and the live competition (lowest seller price, seller count, USDC listed), not 30-day history. When a named buy app has no open offer, the reply says why in plain words and quotes the cheapest open route instead. Fees are explained in human units when relevant. Trading takes place on the existing destination sites.

People supply a wallet address or deposit ID; internal source identifiers never become user instructions.

Use ordinary Markdown links to the verified destinations. Do not suggest arbitrary custom cards, payment buttons or HTML support. Public sources and units live in the skill; user watch settings never belong in a public template.

## Repository and launch artwork

The approved identity is a flat cobalt coin-shaped Peerboop character with dark capsule eyes and a friendly wave, informed by actual Grok marketplace avatars. The user rejected the earlier linked-circle icon. Use the approved unchanged character in native avatars and repository/launch layouts. A simple trading ticket carries the descriptor and four actual capabilities. It is an illustration, not a product screenshot. No invented balances, prices, activity or testimonials.

- USDC blue: `#2775CA`, the main brand plane and action accent.
- Ink: `#17212E`, primary text.
- Paper: `#F4F7FB`, open background.
- White: `#FFFFFF`, reverse text and ticket surface.
- Rule: `#C8D5E5`, quiet dividers.
- System sans for labels and headings; system monospace only for small ticket details. No downloaded fonts.
- Flat front-on geometry, consistent straight rules and generous whitespace. No gradients, fake lighting or decorative charts.
- The memorable element is the ticket, not a generic chat-bubble collage. README text carries the install action and details so small SVG text is never required for comprehension.

## Marketing images

Still images only; there are no videos. Each image centres an unedited crop of a real conversation with the published bot. Only the Peerboop mark sits outside the chat; no headline or footer copy. Capture dates are recorded in the media notes. Never repaint, retype or reorder a reply, and never hide a fee. Crop away the sidebar, account details and setup messages. Text in the crop must read at phone-feed width (about 390 px). Layout sources live beside the PNGs in `docs/assets/marketing/` and provenance in [Media notes](docs/launch/MEDIA.md).

## Review

Inspect repository art at 390 and 1440 widths on light and dark surroundings. Inspect native chat at a narrow viewport and desktop width. Check real source links, text clipping, readable numerals and private content. GitHub and Grok control their own themes; this repo does not implement a theme switch or animation.
