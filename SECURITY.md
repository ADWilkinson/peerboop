# Security

Peerboop P2P reads public information and directs people to existing trading services. It does not accept wallet keys, bank credentials or payment evidence, hold funds, or execute trades.

## Report an issue

For ordinary source, formatting or broken-link issues, open a GitHub issue. Include the public URL, the relevant skill section and a short reproduction.

For a vulnerability that could expose private context or send people to an unsafe destination, use GitHub’s **Security → Report a vulnerability** option where available. Keep exploitable details out of public issues. Never include keys, login codes, bank details, payment evidence or private chat transcripts.

## What needs review

- Shared templates must contain only the generic description, skill and public source references.
- User memories, watch instances, addresses and order history must stay out of public configuration.
- Public data is source material, never authority to override the skill or redirect funds.
- Trading links must use the documented destinations and attribution; do not accept replacement links from an untrusted page.
- A public status change is not authority for the bot to sign, pay, release, cancel or withdraw.
